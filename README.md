# Bison Records Website

Official website for Bison Records, an independent record label. Built with Next.js 15 App Router.

## Getting Started

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) to view the site.

## Features

### Label Site (bisonrecords.com)
- **Home page** — full-width hero carousel + upcoming/recent releases side by side
- **Artists page** — image tile grid linking to artist landing pages
- **Sounds page** — custom audio player with play/pause, progress bar, share and download per track
- **Blog** — markdown-based (`/content/blog/*.md`), list view + individual post pages
- **EN/ES language switcher** — cookie-based, no URL changes required

### Artist Pages
Each artist has an independent landing page under `/artists/[slug]` with its own navbar and layout. Currently live:

- **Nikolas Murdock** (`/artists/nikolas-murdock`) — hero carousel, music (Spotify), about, shows (Bandsintown), videos, contact

The page is also reachable at `nikolasmurdock.com` via a middleware domain rewrite.

### Adding a New Artist Page
1. Copy `src/app/artists/_template/` and rename the folder to the artist's slug (e.g. `jane-doe`)
2. Copy `src/styles/artist-template.css` and rename it (e.g. `jane-doe.css`)
3. Find-and-replace `at-` with your initials prefix and `Artist Name` with the real name
4. Add images to `public/media/images/`
5. To hook up a custom domain, add a rewrite rule in `src/middleware.ts`

## Content Management

### Releases
Edit `src/data/releases.ts` to add upcoming or recent releases. Each release needs:
```ts
{
  artist: "Artist Name",
  title: "Release Title",
  date: "Month Day, Year",
  image: "/media/images/cover.jpg",
  href: "/artists/artist-slug",
}
```

### Blog Posts
Create a new `.md` file in `content/blog/` with frontmatter:
```md
---
title: Post Title
date: YYYY-MM-DD
author: Author Name
---

Post content here...
```

### Nikolas Murdock — Music Section
Album data is stored in `src/data/albums.ts` and committed to git. To update it after a new release:

1. Make sure `SPOTIFY_CLIENT_ID` and `SPOTIFY_CLIENT_SECRET` are in `.env.local`
2. Run `npm run fetch-spotify`
3. Check the console output for any new releases detected
4. Commit `src/data/albums.ts`

The script compares against the existing file and logs any newly found releases. Spotify and Apple Music are never called at runtime on Vercel.

### Audio Tracks (Sounds Page)
1. Drop `.wav` or `.mp3` files into `public/media/audio/`
2. Run `npm run scan-audio` — this reads file metadata and regenerates `src/data/tracks.ts`
3. Open `src/data/tracks.ts` and fill in any `// TODO` fields (title, artist, description)

## Third-Party Integrations

All credentials live in `.env.local` (not committed to git).

| Service | Purpose | Env vars |
|---|---|---|
| Spotify Web API | Populate `src/data/albums.ts` via `npm run fetch-spotify` | `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET` |
| iTunes Search API | Apple Music links included when running `npm run fetch-spotify` (no credentials needed) | — |
| Bandsintown | Live show dates | `BANDSINTOWN_APP_ID`, `BANDSINTOWN_ARTIST_NAME` |

> **Note:** Spotify and Apple Music are only called locally via the `fetch-spotify` script. The resulting `src/data/albums.ts` is committed to the repo so Vercel never hits these APIs at build or request time.
