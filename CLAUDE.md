# Bison Records — Developer Notes

## Data & media architecture

Content (artists, releases, tracks, videos, events, album details, blog posts) lives in Neon
Postgres, queried via Drizzle (`src/db/schema.ts`, `src/db/index.ts`). Media files (images,
audio, video) live in Vercel Blob, uploaded via `src/lib/blob.ts`. `src/data/albums.ts` (a
build-time cache of the Spotify API, regenerated by `npm run fetch-spotify`) and
`src/data/destinations.ts` are the only content still kept as git-tracked flat files.

The admin CMS (`/admin`, dev-only — gated by `NODE_ENV !== "development"`) reads and writes
Neon/Blob directly through `/api/admin/*` routes; there's no separate persistence layer to keep
in sync.

`DATABASE_URL` (as `BR_DATABASE_URL` from the Neon integration) and Blob credentials
(`BLOB_STORE_ID`, plus `BLOB_READ_WRITE_TOKEN` for local dev — see below) come from `.env.local`,
pulled via `vercel env pull --environment=preview` (Secret-type values still need pasting in from
the Vercel dashboard's Storage tab, since the CLI redacts them).

### Blob auth locally

The `@vercel/blob` SDK tries ambient OIDC auth first, which only works for Preview/Production —
local dev needs an explicit `BLOB_READ_WRITE_TOKEN` in `.env.local` (create one from the Blob
store's dashboard, or `vercel blob signed-token`... except that command also requires OIDC, so
the dashboard is the reliable path). `src/lib/blob.ts` passes this token explicitly so it isn't
shadowed by the OIDC-first resolution.

## Video uploads

Run ffmpeg locally to create optimized versions before uploading a new video — the hero and
video-gallery players expect explicit WebM and MP4 URLs (no more derive-by-basename convention).

```bash
# Replace FILENAME with the base name (no extension)

# Optimized MP4 (H.264, web-ready)
ffmpeg -i FILENAME.mp4 \
  -c:v libx264 -crf 28 -preset slow -movflags +faststart -an \
  FILENAME-opt.mp4 -y

# WebM (VP9, smaller for modern browsers)
ffmpeg -i FILENAME.mp4 \
  -c:v libvpx-vp9 -crf 33 -b:v 0 -an -deadline good -cpu-used 2 \
  FILENAME.webm -y
```

The `-opt.mp4` is typically ~60% smaller than the raw export. The `.webm` is another option
browsers prefer when available. Upload both through the admin Videos page (`/admin/videos`) —
each gets its own dropzone that uploads straight to Blob and fills in the matching URL field.
